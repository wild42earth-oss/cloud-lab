# Methodology, dataset and scope

## Relationship to the paper
Weng et al. (2026), *Group-Evolving Agents: Open-Ended Self-Improvement via Experience Sharing*, motivates selecting a parent group and allowing its members to learn from shared experience. This prototype implements those high-level concepts in a deliberately small controlled setting.

## Dataset
The versioned file `data/problems.json` is a manually authored synthetic benchmark of 12 Python function tasks. Each task contains a task ID, short description, category and four input/expected-output test pairs. Categories are arithmetic, predicates, comparisons, iteration, strings and lists. The data is stored as JSON and loaded with schema checks. There is no train/test split; all tasks are used for evaluation in this mechanism demonstration. State this clearly in the report.

## Agents
Six agents use fixed strategy-order profiles over a finite portfolio of twelve known, tested functions. The profile controls the order in which candidate functions are evaluated. This is not an LLM code-generation system and does not synthesize new programs.

## Independent baseline
Each agent evaluates the benchmark without consulting the experience store. It retains the same strategy profile throughout the experiment.

## Group method
After each generation, a parent group of size two is selected. The score is 0.7 times mean task accuracy plus 0.3 times the proportion of distinct strategy descriptors in the group. Successful task/strategy observations from selected agents are recorded. During the next generation, all agents can use the most frequent validated strategy for a task category as a candidate-order preference.

## Validation and metrics
Only records corresponding to benchmark tasks that pass all four tests are shared. Metrics include per-agent task success rate, mean and standard deviation across agent observations, and task evaluations. The novelty measure is a simple categorical proxy, not KNN novelty.

## Limitations
The benchmark is small and synthetic, the strategy portfolio is finite, all tested tasks can be solved by the reference function set, and agents do not use an LLM. The experiment cannot establish performance on real repositories, complex software engineering tasks, SWE-bench Verified, Polyglot, or the full GEA system. Use only metrics actually generated by the experiment runner.
